BLOCKS – Installation and Deployment Guide


1. Required Accounts

Before you start, you need two accounts:

1. GitHub account
	•	Create an account at https://github.com
	•	GitHub is used to host the source code and manage your own copy of the app.

2. Railway account
	•	Create an account at https://railway.app
	•	Railway is used to deploy and host the BLOCKS app online.
	•	During setup, Railway will ask you to connect your GitHub account.

⸻

2. Fork the BLOCKS Repository
	1.	Go to the BLOCKS repository:
https://github.com/runehlomholt/BLOCKS
	2.	Click the “Fork” button (top right).
	•	This creates a copy of the repository under your own GitHub account.
	3.	You will now have your own version of BLOCKS, for example:
https://github.com/YOUR_USERNAME/BLOCKS

(Optional – local copy)

If you want to work locally on your computer:
	•	Clone your fork using Git:
git clone https://github.com/YOUR_USERNAME/BLOCKS.git
	•	Enter the project folder:
cd BLOCKS

⸻

3. Prepare the Vignette Text Files (IMPORTANT)

BLOCKS uses plain .txt files organised in a specific folder structure to define vignette content.
Each vignette is stored as a separate text file, and the folder structure determines how vignettes are grouped and loaded by the app.

General rules
	•	Vignette content must be written in plain text (.txt) files.
	•	Files must be placed in the correct folder structure inside the repository.
	•	Folder and file names must match what the app expects.
	•	The app reads vignette content directly from these files at runtime.

Typical structure (example)

BLOCKS/
├── vignette_content/
│   ├── Set_1/
│   │   ├── vignette_01.txt
│   │   ├── vignette_02.txt
│   │   └── vignette_03.txt
│   ├── Set_2/
│   │   ├── vignette_01.txt
│   │   └── vignette_02.txt
│   └── ...
├── app files
└── configuration files

The included illustrative design can be regenerated from the repository root:

Rscript scripts/run_design_workflow.R

This creates 24 balanced sets containing four illustrative morning-coffee
vignettes each and updates vignette_content.

The workflow is divided into numbered stages in scripts/. Study settings are
kept in config/workflow_config.R so factor levels, block size, random seed, and
text merge order can be changed without editing the processing scripts.

Canonical design outputs are stored in outputs/. The .rds files preserve R
object types and are used between workflow stages. The .xlsx files are intended
only for human inspection.

Text file requirements
	•	Each .txt file should contain one complete vignette.
	•	Write the vignette exactly as it should appear to participants. Generate vignettes using the R script.
	
⸻

4. Deploy the App on Railway
	1.	Log in to Railway:
https://railway.app
	2.	Create a new project:
	•	Choose “Deploy from GitHub repository”.
	3.	Connect GitHub to Railway (if not already connected):
	•	Authorise Railway to access your GitHub repositories.
	4.	Select your forked BLOCKS repository from the list.
	5.	Configure deployment:
	•	Add a strong, unique EXPORT_KEY environment variable in Railway.
	•	Set DESIGN_VERSION and APP_VERSION so exported records identify the deployed experiment.
	•	Railway supplies DATABASE_URL when PostgreSQL is attached.
	•	Railway automatically assigns a PORT and builds the app.
	6.	Click “Deploy”.

Railway will:
	•	Build the app
	•	Start the server
	•	Generate a public URL for your BLOCKS instance

⸻

5. Updating the App
	•	Any change you push to your GitHub repository (including updated vignette .txt files)
will automatically trigger a new deployment on Railway.
	•	This makes it easy to update vignette content without redeploying manually.

⸻

6. Optional: Run BLOCKS Locally

If you want to test the app locally before deploying:
	1.	Install required software (see README):
	•	Programming language runtime (e.g. Python)
	•	Required libraries (via requirements.txt or equivalent)
	2.	Install dependencies:
pip install -r requirements.txt
	3.	Start the app locally following the README instructions.
	4.	Verify that:
	•	Vignette text files load correctly
	•	Vignettes appear as expected in the interface
	•	Database migrations run with: alembic upgrade head
	•	The export endpoint rejects requests without the configured EXPORT_KEY
	•	The database monitor runs after DATABASE_URL is set:
		Rscript scripts/03a_monitor_database.R
	•	A downloaded CSV passes:
		Rscript scripts/03b_check_export_integrity.R vignette_data.csv

⸻

7. Troubleshooting
	•	Railway cannot see your repository
	•	Check that GitHub is connected in Railway settings.
	•	Deployment fails
	•	Open the Railway logs to inspect build or runtime errors.
	•	Common issues include missing folders or incorrectly named vignette files.
	•	Vignette content does not appear
	•	Double-check folder names and file locations.
	•	Ensure .txt files were committed and pushed to GitHub, not only saved locally.

⸻

8. Summary

To run BLOCKS, you must:
	•	Create GitHub and Railway accounts
	•	Fork the BLOCKS repository
	•	Prepare and correctly place vignette .txt files
	•	Deploy the forked repository via Railway

Once deployed, BLOCKS is accessible via a public URL and updates automatically whenever you push changes.
